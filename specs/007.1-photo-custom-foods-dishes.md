# Plan: Photo Support for Custom Foods and Dishes

## Context
Custom foods and dishes have no user-uploadable photo support today. FatSecret API foods automatically populate `food_photos` via the search service. This feature adds up to 1 user-uploaded photo per custom food or dish in two formats: **thumb** (small, fast, for search/list views) and **display** (larger, optimized, for detail/modal views). Storage: Vercel Blob. Resizing: browser Canvas API client-side before upload (user's choice).

Photos are managed on **edit forms only** — create flows are unchanged. After creating a food or dish, the user can immediately go to edit to add a photo.

---

## Schema Changes

### 1. New `dish_photos` table — `src/server/db/schema.ts`
```typescript
export const dishPhotos = pgTable('dish_photos', {
  id: uuid('id').primaryKey().notNull().$defaultFn(() => uuidv7()),
  dishId: uuid('dish_id')
    .notNull()
    .references(() => customDishes.id, { onDelete: 'cascade' })
    .unique(),
  thumb: varchar('thumb', { length: 500 }),    // ~300px, JPEG 65%
  highres: varchar('highres', { length: 500 }), // ~900px, JPEG 85%
  createdAt: timestamp('created_at').defaultNow().notNull(),
}, (table) => [index('dish_photos_dish_id_idx').on(table.dishId)]);
```
Add `dishPhotosRelations` and export insert/select schemas.

### 2. Custom foods — no schema change
Custom foods live in `foods` table; `food_photos` already links via `foodId` with `thumb`/`highres` columns. Reuse as-is.

### Migration
Run `npm run db:push` after schema changes.

## New Files

### `src/lib/image-resize.ts` (client-only utility)
```typescript
export async function resizeForUpload(file: File): Promise<{ thumb: Blob; display: Blob }>
```
- Loads file into `HTMLImageElement` via `URL.createObjectURL`
- Uses canvas to produce two JPEG blobs:
  - `thumb`: max 300px on longest side, quality 0.65
  - `display`: max 900px on longest side, quality 0.85
- Returns both blobs; revokes object URL when done

### `src/app/api/foods/custom/[foodId]/photo/route.ts`
- `POST`: FormData with `thumb` (Blob) + `display` (Blob) fields
  - Verify user owns the food (`foods.userId = user.id`)
  - Upload both to Vercel Blob via `put(path, blob, { access: 'public' })`
  - Upsert row in `food_photos` (`thumb`, `highres` columns)
  - Return `{ thumb: string; highres: string }`
- `DELETE`: Delete from Vercel Blob + delete `food_photos` row; return 204

### `src/app/api/dishes/[dishId]/photo/route.ts`
- Same pattern as above but for `dish_photos` table
- Verify ownership via `customDishes.userId = user.id`

### `src/components/photo-uploader.tsx` — generic, reusable
```tsx
interface PhotoUploaderProps {
  currentThumb?: string | null;
  uploadUrl: string;                                // e.g. '/api/foods/custom/abc/photo'
  onUploaded: (thumb: string, highres: string) => void;
  onDeleted: () => void;
  disabled?: boolean;
  label?: string;       // e.g. "Food Photo", "Dish Photo"
  hint?: string;        // optional sub-label
}
```

**Three input methods — all supported:**
1. **Browse files** — hidden `<input type="file" accept="image/*">`, triggered by clicking the drop zone
2. **Drag and drop** — drop zone with `onDragOver` / `onDrop` handlers; visual "active" state on drag-over
3. **Paste** — `onPaste` handler on the container (or `document` paste event while focused); extracts `DataTransfer.items` for `image/*` MIME types

**Internal state machine:** `idle → selecting (drag-over) → processing (canvas resize) → uploading (fetch) → done | error`

**UX details:**
- Drop zone shows dashed border, icon, "Drop image, paste, or click to browse" hint text
- When photo exists: shows thumbnail, ×-delete button, and "Replace" affordance on hover
- Upload spinner overlay during processing/uploading states
- Error message inline if upload fails
- `disabled` prop disables all interactions (used during form submit)

**Designed for reuse** — no food/dish-specific logic inside; all domain specifics passed via props
